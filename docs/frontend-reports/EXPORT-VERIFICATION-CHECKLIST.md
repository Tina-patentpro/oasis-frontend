# 导出功能验证清单（Phase 5）

本文档用于指导 QA / 开发在 Mock 与 真实 API 两种模式下验证导出链路。覆盖的组件：会话导出、项目导出、历史数据导入（合并内容后触发下载）。

## 1. 前置检查

- 确认 `npm install` 已完成，项目可以正常启动。
- 根据验证目标设置环境变量：
  - Mock 模式：`VITE_USE_MOCK=true`
  - 真实模式：`VITE_USE_MOCK=false` 且 `VITE_API_BASE_URL` 指向后端网关。
- 在真实模式下，确保后端实现以下端点并返回可下载链接：
  - `POST /sessions/{id}/export`
  - `POST /sessions/batch-export`
  - `POST /projects/{id}/export`
  - `POST /history/export`

> 如后端不支持直接可下载链接，需要保证返回的地址在浏览器可访问，或在前端改为 Blob/stream 下载。

## 2. 会话导出（`useSessionManagement`）

| 场景      | 步骤                                                                                     | 期望结果                                                                |
| --------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Mock 下载 | 1. `VITE_USE_MOCK=true` 启动<br>2. 在工作区侧栏打开任意会话的“更多”菜单<br>3. 点击“导出” | 浏览器自动下载 JSON 文件，文件名包含时间戳；通知提示 “导出已开始下载”。 |
| Mock 兜底 | 1. 人为修改 `sessionService.exportSession` 使其抛错（或断网）<br>2. 重复导出操作         | 浏览器下载 Markdown 占位文件，通知提示 fallback。                       |
| 真实模式  | 1. `VITE_USE_MOCK=false` 并配置有效后端<br>2. 导出会话                                   | 下载链接指向后端返回的文件；若返回状态为 `pending`，提示任务提交成功。  |

验证要点：

- 文件内容包含会话标题或占位提示。
- 下载文件名符合 `src/utils/download.ts#createTimestampedFileName` 规范。

## 3. 项目导出（`useProjectExport`）

| 场景      | 步骤                                                                                          | 期望结果                                                |
| --------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Mock      | 1. `VITE_USE_MOCK=true`<br>2. 打开任意项目详情，点击“导出”<br>3. 在对话框保持默认选项直接导出 | 生成 JSON 文件，字段含 `items`/`summary`。              |
| Mock 兜底 | 关闭网络或修改 `statisticsService.exportProjectData` 抛错后导出                               | 浏览器下载占位 JSON，包含 `note: "导出服务不可用"`。    |
| 真实模式  | 真实后端返回可下载链接                                                                        | 浏览器从真实 OSS/后端下载压缩包或文档；对话框自动关闭。 |

验证要点：

- `ExportSelectionDialog` 在导出过程中禁用按钮，导出完成后自动关闭。
- 占位文件路径正确无乱码。

## 4. 历史资料导入（下载合并内容）

| 场景     | 步骤                                                               | 期望结果                                                                              |
| -------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Mock     | 打开历史资料选择弹窗，勾选多条记录并确认                           | `onConfirm` 收到合并后的文本内容；备用下载逻辑（如果将来接入）可重用 `downloadText`。 |
| 真实模式 | 配置后端 `historyService.exportHistoryData` 返回带有效期的下载地址 | 通过 `downloadFromUrl` 触发浏览器下载，URL 过期前可重复使用，过期后需提示刷新。       |

## 5. 手动巡检清单

- [ ] 不同导出入口使用的文件名格式一致（`name-YYYY-MM-DDTHH-mm-ss`）。
- [ ] Mock 模式不会调用真实后端，所有下载使用 data URL 或本地 Blob。
- [ ] 真实模式导出失败时，界面能给出明确错误提示并保留 fallback（会话/项目）。
- [ ] `npm run lint` 无新增错误（允许存在历史 warning）。
- [ ] `npm run build` 成功（编译通过即视为后端联调前验收完成）。

## 6. 常见问题

| 问题                | 排查建议                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| 下载文件为空        | 检查后端返回的 `downloadUrl` 是否指向受限资源；必要时将响应改为 Blob 流供前端 `downloadBlob`。 |
| Fallback 文件未触发 | 确认异常被抛出，且未被 Promise 吞掉；检查通知逻辑在 `catch` 中是否执行。                       |
| Windows 文件名异常  | `sanitizeFileName` 会替换非法字符，如仍有问题，确认后端返回标题是否包含控制字符。              |

---

如需扩展新的导出入口，请确保复用 `src/utils/download.ts` 提供的工具，并在本清单内追加新的验证步骤。
