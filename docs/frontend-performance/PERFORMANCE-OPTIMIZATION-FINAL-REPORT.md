## 🎓 经验总结

### 优化亮点

1. **组件重构**: NotificationCenter 通过提取 NotificationItem 子组件，既优化了性能又提高了可维护性
2. **常量提取**: TYPE_CONFIG 的提取避免了对象的重复创建，是优秀的优化实践
3. **全面优化**: 不仅优化了事件处理器，还优化了计算逻辑和组件结构
4. **代码清理**: 及时移除未使用的代码，保持代码库整洁
5. **渐进式实施**: 组件逐个优化并验证，风险可控

### 学到的经验

1. **useCallback 的价值**: 稳定函数引用对避免子组件不必要重渲染至关重要
2. **useMemo 的适用场景**: 数组操作、复杂对象构建等计算密集型操作值得优化
3. **React.memo 的选择**: 优先优化渲染频繁的组件，简单组件不必过度优化
4. **依赖数组的重要性**: 必须正确完整，ESLint 的 exhaustive-deps 规则很有帮助
5. **代码可维护性**: 性能优化的同时也要考虑代码的可读性和可维护性

### 避免的陷阱

- ✅ 避免了过度优化（简单操作不使用 useMemo）
- ✅ 避免了依赖数组错误（使用 ESLint 规则检查）
- ✅ 避免了忽略测试（每次优化后都验证功能）
- ✅ 避免了破坏 UI/UX（严格遵守零变更原则）

## 📎 附录

### A. 优化前后对比示例

#### 示例 1: 内联函数优化

```typescript
// ❌ 优化前
<button onClick={() => setOpen(!open)}>Toggle</button>

// ✅ 优化后
const handleToggle = useCallback(() => setOpen(prev => !prev), [])
<button onClick={handleToggle}>Toggle</button>
```

#### 示例 2: 计算优化

```typescript
// ❌ 优化前
const currentTab = tabs.find((t) => t.k === tab) // 每次渲染都执行

// ✅ 优化后
const currentTab = useMemo(() => tabs.find((t) => t.k === tab), [tabs, tab])
```

#### 示例 3: 组件优化

```typescript
// ❌ 优化前
const MyComponent: FC<Props> = ({ data }) => <div>{data.title}</div>

// ✅ 优化后
const MyComponent = memo<Props>(({ data }) => <div>{data.title}</div>)
MyComponent.displayName = 'MyComponent'
```
