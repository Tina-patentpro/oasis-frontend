# 产品更新日志

这里记录每次版本发布给用户带来的新增、优化、修复与使用注意事项。

> 维护说明：从 `1.0.0` 开始记录正式版本变更。用户端“版本更新”内容由本文件同步生成。更新后请运行 `npm run changelog:sync`；如需推送订阅通知，再运行 `npm run changelog:notify` 或等待 CI。

## [1.0.7]

### 本次重点

`1.0.7` 在正式部署前完成依赖安全补丁升级，消除当前生产与开发工具链审计发现的已知风险，并修正会话删除请求路由；不改变其他业务流程或已有用户数据。

### 新增

- 本版本无需要单独对外说明的新增项。

### 优化

- 更新图表渲染、内容净化、浏览器路由和构建工具链的兼容补丁版本，保持现有功能与 Node.js 20 运行时不变。
- 完整依赖审计与生产依赖审计不再依赖 `1.0.6` 中记录的 React Router 和 brace-expansion 临时上下文例外。
- 为安全更新后的懒加载图表解析器增加独立体积上限，其他图表资源仍保持原有严格预算，避免扩大首屏资源。
- 补全用户端接口总览与自动契约校验，发布检查会稳定发现全部脚本测试，并对会话删除等 legacy 路径执行方法与契约一致性检查。
- 收紧下载和上传失败诊断，开发日志不再包含签名下载地址、原始业务响应或会话输入内容。
- 设置页剪贴板验收会跟随当前预览地址授权，不再依赖固定端口。
- 刷新浏览器兼容性数据，保持现有目标浏览器范围不变，并消除构建时数据库陈旧提示。

### 修复

- 修复 DOMPurify、Mermaid 与 React Router 已公开安全公告对应的依赖版本问题。
- 修复开发工具链中 js-yaml、nanoid 与 brace-expansion 已公开安全公告对应的传递依赖版本问题。
- 修复删除会话时可能误用项目删除接口的问题，避免把会话编号当作项目编号处理；历史 GET 删除请求统一禁用浏览器缓存。
- 修复项目详情读取误用会话详情路径的问题，项目信息改由现网 `folderdetail` 链路读取，不再把单次工作流记录映射为项目统计。
- 修复 320px 和 375px 窄屏下会话提示遮挡搜索、导出、清空或指令库操作的问题；桌面端仍保持右下角提示。
- 修复危险或不支持的下载地址被拦截后仍可能显示成功的问题；现在会在发起请求前阻止并保留明确的失败与重试状态。

### 需要注意

- 本次更新不迁移账户数据、项目内容或生成文件；会话删除改用现网会话专用接口，远端部署和流量切换仍需按发布流程人工执行并单独验证。
- 本版本只包含兼容补丁级依赖更新，不包含框架、构建工具或设计系统的主版本升级。
- 2026-09-01 真实后端只读与一次性测试会话删除验证通过：测试号码加入频率白名单后完成短信登录；独立会话完整集合按 `151 → 152 → 151` 复核，证明仅本次新增测试会话被删除且其他会话均保留。阿里云日级流控 `isv.BUSINESS_LIMIT_CONTROL` 当前仍被后端错误映射为 `HTTP 500`，目标 `429` 映射继续作为后端整改项。

## [1.0.6]

### 本次重点

`1.0.6` 修复窄屏认证布局与主地标，完善生产安全、依赖、缓存和性能验收链路。

### 新增

- 新增认证页多视口、首屏预算与唯一主地标回归测试。
- 新增生产构建安全检查、nginx 候选生成器和只读线上验证器。

### 优化

- 生产 CSP 与开发来源分离，新增表单提交限制和防嵌入响应头。
- 为哈希资源、真实 404 和分阶段 HSTS 提供可审计 nginx 候选配置。
- 将 React Router 升级至 7.18.1，关闭适用于当前声明式前端的已修复安全公告，并为仅影响 RSC 能力的剩余公告增加版本、模式和到期日守卫。
- 升级 js-yaml、PostCSS 和 brace-expansion 的兼容安全补丁，并新增覆盖开发工具链的完整依赖审计门。

### 修复

- 修复 280–473px 短信登录和注册验证码区域横向溢出。
- 修复 GlobalLayout 与 App 产生嵌套 main 地标的问题。

### 需要注意

- 生产 nginx 变更仍需先执行只读基线、nginx -t 和分阶段人工上线；本次不修改远端配置。
- React Router 的 RSC 公告上下文例外须在 2026-10-31 前复查；项目一旦引入 RSC 或框架模式，生产依赖门会立即阻断。
- brace-expansion 的开发工具链公告例外须在 2026-08-31 前复查；它被自动限制为非生产依赖，运行时代码一旦引用即阻断。

## [1.0.5]

### 本次重点

`1.0.5` 重点修复历史会话切换和手机窄屏显示问题，避免旧聊天内容与当前记录混淆，并让 320px 等窄屏设备上的对话操作保持完整可见。

### 新增

- 本版本无需要单独对外说明的新增项。

### 优化

- 历史记录会先显示加载状态，详情恢复成功后再切换为当前记录；详情加载失败时会保留当前状态并提示失败，不再误报成功；快速连续点击时只保留最后一次选择，减少旧请求覆盖新内容。
- 对话栏因窄屏自动收窄时不再覆盖用户保存的桌面宽度偏好，返回宽屏后会按当前布局恢复合适宽度。
- 手机窄屏下侧栏、工作流和对话区域会互斥显示；切换成功后焦点会进入新区域，会话菜单在键盘聚焦时保持可见。

### 修复

- 修复在 Full 对话模式中打开工作流或旧式历史记录后仍显示上一段聊天内容的问题，所选记录现在会切换到对应的聊天或工作流界面。
- 修复对话模式关闭时打开聊天记录仍可能误报恢复成功的问题；现在会保留当前界面并提示先启用对应的对话模式。
- 修复历史记录列表与详情中的项目归属不一致时，恢复后的聊天或工作流可能关联到旧项目的问题；恢复时以详情中的归属为准，明确无项目的记录不会被重新绑定。
- 修复 320px 窄屏下 Full 对话栏仍按 360px 最小宽度渲染，导致搜索、消息和输入操作横向裁切的问题。
- 修复宽屏横向分栏中输入材料标题和“新会话”被项目选择器挤压成竖排的问题；标题栏现在会按输入区的实际宽度重新排布，在 320px、375px 和桌面分栏中均保持文字横排且不横向溢出。
- 更新内容安全过滤组件，修复依赖审计发现的低风险安全问题，继续降低特殊富文本或图表内容触发异常脚本的风险。

### 需要注意

- 本次更新主要影响历史会话恢复、项目关联和对话栏响应式显示，不改变已有项目、历史记录或生成文件。

## [1.0.4]

### 本次重点

`1.0.4` 重点提升工作区和右侧内容栏的稳定性，减少历史记录、图表内容和特殊操作在加载或渲染失败时对用户造成的中断，同时补充了发布前的检查证据。

### 新增

- 本版本无需要单独对外说明的新增项。

### 优化

- 工作区顶栏在手机窄屏下改为双行排布，侧边栏、对话模式、后台任务、通知和用户菜单不再互相遮挡。
- 工作区导航和页面布局进一步整理，在项目管理、历史记录和右侧内容查看之间切换时更稳定。
- 设置页体验继续打磨，常用状态、提示和覆盖测试更完整。
- 推荐码复制、生成等全局操作提示现在会在页面上显示，并由辅助技术及时播报。
- 推荐奖励会分别显示加载中、加载失败、未分配和正常数据，失败时可直接重新加载；推荐次数也会按系统配置正确显示“不限”或“已停用”。
- 指令库下载弹窗补充加载失败重试和复制结果提示，网络或剪贴板不可用时不再误显示为空数据或静默失败。
- 右侧内容栏的操作确认改为页面内确认弹窗，减少浏览器原生弹窗带来的突兀感。
- 发布检查记录补充到项目文档中，便于后续上线前复核。

### 修复

- 修复登录后返回工作区时丢失查询条件和页面锚点的问题，重新登录后会回到原来的工作位置。
- 修复带进度的文件下载在服务端返回错误时仍可能被视为成功，以及连续更换头像预览后本地资源未及时释放的问题。
- 支付链接无效时不再把订单响应写入浏览器控制台，减少不必要的账户与支付信息暴露。
- 加强右侧内容栏的异常兜底，Markdown 解析、图表渲染或内容组件加载异常时会优先显示可理解提示，避免整块区域直接崩溃。
- 加强 Mermaid 图表内容的安全处理和渲染保护，减少特殊图表源码导致显示失败的情况。
- 改善从项目管理历史记录恢复内容时的状态处理，降低旧请求影响新内容显示的可能。
- 移除设置页中的演示推荐码和本地随机生成逻辑；当前账户没有推荐码时，改为调用后端生成接口并展示后端返回的真实推荐码。
- 移除设置页中无真实数据来源的导出入口，避免生成无法用于恢复的模拟文件。
- 补齐独立“个人信息和推荐奖励”页面的后端邀请码生成入口，并修正邀请记录末页仍可继续翻页的问题。
- 会话菜单导出改为读取现有后端会话详情后生成真实 ZIP，移除服务端导出失败时下载占位内容的误导行为。
- 修复搜索回车、微信支付核验、后台任务轮询和文件下载弹窗在快速重复操作时可能重复请求、提前关闭或被旧结果覆盖的问题。
- 修复个人资料连续保存时，较早的成功提示定时器可能提前清除较新提示的问题。
- 修复本地开发或预览环境导出真实会话时，生成附件因跨域限制无法写入 ZIP 的问题。
- 修复重新打开历史会话后，已生成附件短暂出现又被清空、导致下载按钮不可用的问题。
- 修复开发环境严格模式下，空推荐码账户点击生成后可能无法展示后端返回结果的问题。
- 统一工作区直接刷新时的浏览器标题，避免显示旧的登录页标题。

### 需要注意

- 登录状态改为当前浏览器会话内最长保留 1 小时；关闭浏览器或从旧版本升级后需要重新登录。
- 线上旧版本如果仍显示 `ContentRenderer加载失败` 或网络失败提示，需要等本版本部署后再复测确认。
- 本次更新主要影响工作区、设置页、右侧内容栏和发布检查记录，不改变已有项目数据和生成文件。

## [1.0.3]

### 本次重点

`1.0.3` 重点优化右侧对话栏的历史恢复和资料读取体验，尤其提升语义生图历史图片的显示稳定性，并让指令、读取和项目关联等常用操作更符合用户预期。

### 新增

- 本版本无需要单独对外说明的新增项。

### 优化

- 右侧对话栏的指令类内容统一插入到输入框开头，读取生成结果和读取历史资料等资料类内容统一追加到末尾，减少覆盖已有输入的情况。
- 右侧对话栏的导出、关联、读取、清空对话和指令库等操作位置进一步整理，常用按钮更集中，底部区域在窄宽度下更稳定。
- 有序列表建议入口改得更像可点击操作，提示文案也补充了“指令会插入到开头、读取资料会追加到末尾”的说明，降低使用困惑。
- 历史会话恢复时会更干净地处理生成结果文本，避免把思考过程等不适合继续编辑的内容带回输入框。

### 修复

- 修复语义生图历史会话中，图片地址藏在历史正文里时无法正确显示的问题。
- 修复部分历史图片使用后端生成文件地址时，预览区无法稳定识别和加载的问题。
- 修复切换有图和无图历史会话后，图片状态可能残留或显示不一致的问题。
- 修复有序列表、读取生成结果、读取历史资料写入输入框时容易覆盖原有内容的问题。

### 需要注意

- 语义生图历史图片仍依赖原图片地址可访问；如果网络较慢，图片可能会短暂延迟显示。
- 本次更新主要影响右侧对话栏、历史恢复和输入写入体验，不改变已有项目数据和已生成文件。

## [1.0.2]

### 本次重点

`1.0.2` 重点优化生成结果和输入预览的稳定性，减少内部参数名、列表序号丢失、图表误判和预览状态残留带来的干扰。

### 新增

- 本版本无需要单独对外说明的新增项。

### 优化

- 输入材料和对话输入继续支持 Markdown 编辑与预览切换，清空后重新输入会回到可编辑状态。
- 右侧对话输入区的附件、输入高度和 Markdown 编辑/预览按钮调整到同一条工具栏，按钮排列更清楚，输入框左侧留白也恢复正常。
- 生成结果预览统一把 `生成内容` 识别为主文本输出名称，同时兼容旧结果中的 `输出内容`，不同工作流的正文展示更一致。

### 修复

- 修复了生成结果预览中显示 Dify 输出参数名的问题，同步生成、异步生成和历史会话恢复都会只展示实际输出内容。
- 修复了生成结果预览中有序列表序号不显示的问题，列表层级和阅读顺序更清楚。
- 修复了输入预览清空后再次输入可能自动跳回预览的问题，继续编辑更顺畅。
- 修复了普通英文句子以 Pie、Gantt、Journey、Timeline、Mindmap 等词开头时可能被误判为 Mermaid 图表的问题。

### 需要注意

- 建议后续工作流的主文本输出名称统一配置为 `生成内容`；旧的 `输出内容` 仍会被兼容处理。
- 本次更新只影响预览显示和版本记录，不影响已生成文件的下载与使用。

## [1.0.0]

### 本次重点

`1.0.0` 是产品首个正式待发布版本，重点把内容生成、项目管理、界面体验和基础结构整理到可对外发布的状态。

### 新增

- 页面和弹窗支持更细粒度的按需加载，常用界面打开更快，等待时间更短。
- 新增虚拟列表能力，在内容较多的场景下浏览更流畅。
- 项目管理支持更灵活的自定义字段配置，可按业务需要补充项目信息。
- 导出支持“快速导出”和“精确导出”两种方式，便于按场景选择输出范围。
- 帮助与说明文档做了集中整理，后续查找产品说明和使用资料会更方便。
- 全局样式、主题和动画基础能力整理得更完整，后续界面表现更容易保持一致。
- 顶部用户菜单新增“版本更新”入口，现在可以直接在产品里查看当前版本说明。

### 优化

- 对话相关按钮的视觉反馈更明显，悬停、点击和激活状态更易辨认。
- 右侧对话输入框新增“紧凑 / 标准 / 展开”三档高度切换，输入短问题和长段内容时都更方便调整。
- 右侧对话输入框的高度切换改成更紧凑的分段开关样式，并去掉了额外说明字样，占位更小，常用档位更容易一眼看懂。
- 右侧对话底部按钮区在窄宽度下的排布更稳定，单个功能按钮不再容易被单独挤到下一行。

## 版本说明

### 版本号规则

使用语义化版本 `主版本号.次版本号.修订号`：

- **主版本号**：有较大变化，可能会影响原有使用习惯或兼容方式。
- **次版本号**：在原有能力基础上新增功能或做出明显优化，通常不影响正常使用。
- **修订号**：以问题修复和稳定性改进为主，通常不改变主要使用方式。

### 栏目填写规则

- 每个版本固定包含：`本次重点`、`新增`、`优化`、`修复`、`需要注意`。
- 如果某个栏目暂无内容，统一写：`本版本无需要单独对外说明的 X 项。`
- `本次重点` 只写 1 段，用来概括这次发布最值得用户关注的变化。

### 文案口吻规则

- 优先写用户能直接感知到的变化，再补充必要背景。
- 少写实现细节，必须出现术语（专业词）时，尽量补一句白话说明。
- 一条内容尽量回答清楚：这次更新后，用户能得到什么、用起来会有什么变化。
