# session.service.ts 超长文件拆分计划

## 背景

`src/api/services/session.service.ts` 当前有效行数约 599 行，仍在 ESLint 超长文件豁免名单中。目标是在不改变会话列表、详情、重命名、移动、删除、导出占位行为的前提下，把纯辅助逻辑拆出主文件，让主文件回到 500 行以内。

## 计划

1. 先跑会话服务相关测试  
   - 做什么：执行会话服务、工作流列表加载相关测试。
   - 为什么做：确认拆分前行为稳定，后续能对比拆分是否改变行为。
   - 完成标准：相关测试全部通过。

2. 抽出会话数据整理逻辑  
   - 做什么：把 folderId 归一、文件 URL 选择、会话列表字段映射、列表筛选排序、会话详情字段映射移到新文件。
   - 为什么做：这些逻辑不依赖服务类内部缓存，适合独立维护。
   - 完成标准：`session.service.ts` 主要保留接口调用、缓存和业务编排。

3. 移除超长豁免并验证  
   - 做什么：从 `eslint.config.js` 的历史超长文件名单中移除 `session.service.ts`。
   - 为什么做：让后续检查持续防止该文件再次变长。
   - 完成标准：`session.service.ts` 有效行数小于 500，相关测试、类型检查和 lint 全部通过。

## 不做事项

- 不改 API 地址和参数。
- 不改会话缓存策略。
- 不补做未实现的导出接口。
- 不处理剩余的 `ai.service.ts`。
