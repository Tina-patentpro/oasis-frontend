### 🔹 15. POST /api/auth/register - 用户注册

#### ✅ 确认说明

本API是用户注册的核心接口，新用户通过填写注册表单（邮箱、密码、验证码等）创建账户。注册成功后自动登录，跳转到工作区首页。

#### API与UI对应关系

**UI组件位置：** `RegisterPage` > `RegisterForm`

**API响应驱动UI渲染逻辑：**

- 用户在登录页点击"注册"进入注册页
- 填写注册表单并提交
- 前端验证通过后调用本API
- 注册成功后存储token，跳转到工作区

#### 字段映射表格

| API请求/响应字段              | 类型    | UI显示位置 | 组件属性/样式                        | 说明                 |
| ----------------------------- | ------- | ---------- | ------------------------------------ | -------------------- |
| **请求体 - email**            | string  | 邮箱输入框 | `<input type="email" required />`    | 用户邮箱（必填）     |
| **请求体 - password**         | string  | 密码输入框 | `<input type="password" required />` | 用户密码（必填）     |
| **请求体 - confirmPassword**  | string  | 确认密码框 | `<input type="password" required />` | 确认密码（必填）     |
| **请求体 - verificationCode** | string  | 验证码输入 | `<input maxLength={6} />`            | 邮箱验证码（必填）   |
| **请求体 - agreeTOS**         | boolean | 协议勾选框 | `<Checkbox required />`              | 同意用户协议（必填） |
| **请求体 - inviteCode**       | string  | 邀请码输入 | `<input />`                          | 邀请码（可选）       |
| **响应 - userId**             | string  | 用户ID     | 存储到localStorage                   | 新注册用户的ID       |
| **响应 - token**              | string  | 访问令牌   | 存储到localStorage                   | JWT访问令牌          |
| **响应 - refreshToken**       | string  | 刷新令牌   | 存储到localStorage                   | 刷新令牌             |
| **响应 - user.email**         | string  | 用户信息   | 显示在头部                           | 用户邮箱             |
| **响应 - user.nickname**      | string  | 用户昵称   | 显示在头部                           | 默认昵称             |

1. **邮箱验证：** 注册前需验证邮箱，防止恶意注册
2. **密码强度：** 前端和后端双重验证密码强度

5. **自动登录：** 注册成功后自动登录，无需再次输入密码
6. **新人礼包：** 注册成功赠送初始点数，鼓励用户试用

### 🔹 16. POST /api/auth/login - 用户登录

#### ✅ 确认说明

本API是用户登录的核心接口，已注册用户通过邮箱和密码登录系统，获取访问令牌后进入工作区。支持"记住我"功能延长会话有效期。

#### API与UI对应关系

**UI组件位置：** `LoginPage` > `LoginForm`

**API响应驱动UI渲染逻辑：**

- 用户在登录页输入邮箱和密码
- 提交登录表单调用本API
- 登录成功后存储token，跳转到工作区
- 登录失败显示错误提示

#### 字段映射表格

| API请求/响应字段         | 类型    | UI显示位置   | 组件属性/样式                        | 说明                 |
| ------------------------ | ------- | ------------ | ------------------------------------ | -------------------- |
| **请求体 - email**       | string  | 邮箱输入框   | `<input type="email" required />`    | 用户邮箱（必填）     |
| **请求体 - password**    | string  | 密码输入框   | `<input type="password" required />` | 用户密码（必填）     |
| **请求体 - rememberMe**  | boolean | 记住我勾选框 | `<Checkbox>`                         | 保持登录状态（可选） |
| **响应 - userId**        | string  | 用户ID       | 存储到localStorage                   | 用户唯一标识         |
| **响应 - token**         | string  | 访问令牌     | 存储到localStorage                   | JWT访问令牌          |
| **响应 - refreshToken**  | string  | 刷新令牌     | 存储到localStorage                   | 刷新令牌             |
| **响应 - expiresIn**     | integer | 令牌有效期   | 计算过期时间                         | 令牌有效秒数         |
| **响应 - user.email**    | string  | 用户信息     | 显示在头部                           | 用户邮箱             |
| **响应 - user.nickname** | string  | 用户昵称     | 显示在头部                           | 用户昵称             |
| **响应 - user.avatar**   | string  | 用户头像     | `<Avatar src={avatar} />`            | 头像URL              |
| **响应 - user.balance**  | number  | 点数余额     | 显示在头部                           | 当前点数余额         |

### 🔹 17. POST /api/auth/logout - 用户登出

#### ✅ 确认说明

本API用于用户登出系统，清除服务器端的会话状态，并使当前的访问令牌失效。前端需同步清除本地存储的token和用户信息，然后跳转到登录页。

#### API与UI对应关系

**UI组件位置：** `Header` > `UserMenu` > `LogoutButton`

### 🔹 19. DELETE /api/projects/{projectId} - 删除项目

#### ✅ 确认说明

本API用于删除指定的项目。删除项目是敏感操作，会永久删除项目及其关联的所有数据（会话、文件等）。前端需提供二次确认机制，确保用户理解删除的后果。

#### API与UI对应关系

**UI组件位置：** `ProjectSettingsPage` > `DangerZone` > `DeleteProjectButton`

**API响应驱动UI渲染逻辑：**

- 用户在项目设置页的"危险区域"点击"删除项目"
- 弹出确认对话框，要求输入项目名称验证
- 确认后调用本API执行删除
- 删除成功后跳转到项目列表页，并从列表中移除该项目

### 🔹 20. PATCH /api/projects/{projectId}/archive - 归档项目

#### ✅ 确认说明

本API用于将项目归档或从归档中恢复。归档项目不会删除数据，而是将项目标记为非活跃状态，从默认列表中隐藏。归档功能适用于已完成或暂停的项目，保留数据以便后续查阅。

#### API与UI对应关系

**UI组件位置：** `ProjectDetailPage` > `ProjectActions` > `ArchiveButton`

**API响应驱动UI渲染逻辑：**

### 🔹 28. PATCH /api/notifications/read-all - 批量标记已读

#### ✅ 确认说明

本API用于批量标记用户的所有未读通知为已读状态。用户可以一键清空未读通知标识，保持通知中心整洁。

#### API与UI对应关系

**UI组件位置：** `NotificationPanel` > `MarkAllReadButton`

**API响应驱动UI渲染逻辑：**
- 用户打开通知中心查看通知列表
- 点击"全部标记为已读"按钮
- 调用本API更新所有未读通知状态
- 更新成功后清除未读角标和高亮样式

#### 字段映射表格

| API请求/响应字段 | 类型 | UI显示位置 | 组件属性/样式 | 说明 |
|------------|------|-----------|--------------|------|
| **请求体 - filter** | object | 筛选条件 | 可选筛选 | 可选的筛选条件（类型、时间范围等） |
| **请求体 - before** | string | 时间筛选 | ISO 8601时间 | 只标记此时间之前的通知（可选） |
| **响应 - markedCount** | integer | 统计信息 | `已标记{count}条` | 被标记的通知数量 |
| **响应 - success** | boolean | 操作状态 | 成功提示 | 操作是否成功 |
