# 性能监控系统使用说明

## 概述

性能监控系统采用服务器端架构，实现了以下功能：

1. 移除了界面上的性能监控按钮
2. 后台自动收集所有用户的性能数据
3. 数据统一存储在服务器端
4. 服务器端保存最近7天的性能历史记录
5. 提供管理员查询界面，查看所有用户的聚合统计数据

## 系统架构

### 1. 性能数据收集（自动后台运行）

**文件**: `src/monitoring/performance-monitor.ts`

- 每个用户页面加载时自动收集性能指标
- 包括：页面加载时间、DOM解析时间、首次内容绘制(FCP)、最大内容绘制(LCP)、首字节时间(TTFB)、累积布局偏移(CLS)、首次输入延迟(FID)等
- 自动提交到服务器端存储

### 2. 客户端API服务

**文件**: `src/api/services/performance.service.ts`

功能：

- 提交性能数据到服务器：`submitMetrics()`
- 查询性能记录：`getRecords()`
- 获取聚合统计：`getStatistics()`
- 获取最慢页面报告：`getSlowestPages()`
- 清理过期数据：`cleanupExpiredData()`
- 清除所有数据：`clearAllData()`

### 3. 服务器端API

**文件**: `docs/api/performance.yaml`

提供的API端点：

- `POST /api/performance/metrics` - 提交性能数据
- `GET /api/performance/records` - 查询性能记录（支持分页和时间范围过滤）
- `GET /api/performance/statistics` - 获取聚合统计数据
- `GET /api/performance/slowest-pages` - 获取最慢页面列表
- `DELETE /api/performance/cleanup` - 清理超过7天的数据
- `DELETE /api/performance/clear-all` - 清除所有数据

所有API端点都需要管理员权限（Bearer Token认证）。

### 4. 管理员查询界面

**文件**: `src/pages/admin/PerformanceMonitorPage.tsx`
**访问路径**: `/admin/performance`

功能：

- 查看所有用户的性能统计概览（总记录数、平均LCP、平均FCP、数据保留期）
- 按时间范围筛选（1天、3天、7天）
- 性能等级分布图表（所有用户聚合数据）
- 加载最慢的页面 Top 10（跨所有用户）
- 最近100条性能记录列表（所有用户）
- 清理过期数据功能（服务器端操作）
- 清除所有数据功能（服务器端操作）

## 使用方法

### 访问管理员查询页面

1. 登录系统后，在浏览器地址栏访问：

   ```
   http://localhost:5173/admin/performance
   ```

2. 页面会自动加载最近7天的性能数据

### 查看性能数据

页面提供以下信息（所有数据来自服务器端，涵盖所有用户）：

#### 统计卡片

- **总记录数**: 服务器端保存的所有用户性能记录总数
- **平均LCP**: 所有用户的平均最大内容绘制时间
- **平均FCP**: 所有用户的平均首次内容绘制时间
- **数据保留期**: 固定为7天

#### 时间范围选择

- 可选择查看最近1天、3天或7天的数据
- 点击对应按钮即可切换

#### 性能等级分布

- **优秀** (excellent): 加载时间 < 1秒
- **良好** (good): 加载时间 < 2秒
- **一般** (fair): 加载时间 < 3秒
- **较差** (poor): 加载时间 ≥ 3秒

#### 最慢页面列表

- 显示所有用户中加载最慢的前10个页面
- 包含页面URL、平均LCP时间、记录次数

#### 最近记录列表

- 显示最近100条性能记录（所有用户）
- 包含时间、用户ID、页面URL、LCP、FCP、TTFB、CLS、FID等指标
- 显示性能等级

### 数据管理

#### 清理过期数据

点击"清理过期数据"按钮，手动触发服务器端清理超过7天的记录。服务器也会自动定期清理过期数据。

#### 清除所有数据

点击"清除所有数据"按钮，清空服务器上所有用户的性能记录（需要确认，操作不可逆）。

## 性能指标说明

### 主要指标

1. **页面加载时间 (Page Load Time)**
   - 从开始加载到页面完全加载完成的时间
   - 单位：毫秒(ms)

2. **首次内容绘制 (FCP - First Contentful Paint)**
   - 浏览器首次绘制任何文本、图像或非空白canvas的时间
   - 单位：毫秒(ms)
   - 良好标准：< 1800ms

3. **最大内容绘制 (LCP - Largest Contentful Paint)**
   - 视口内最大内容元素可见的时间
   - 单位：毫秒(ms)
   - 良好标准：< 2500ms

4. **首字节时间 (TTFB - Time To First Byte)**
   - 从请求发出到接收到第一个字节的时间
   - 单位：毫秒(ms)
   - 良好标准：< 600ms

5. **累积布局偏移 (CLS - Cumulative Layout Shift)**
   - 页面整个生命周期中所有意外布局偏移的总和
   - 无单位（得分）
   - 良好标准：< 0.1

6. **首次输入延迟 (FID - First Input Delay)**
   - 用户首次与页面交互到浏览器响应的时间
   - 单位：毫秒(ms)
   - 良好标准：< 100ms

### 性能等级标准

基于LCP（最大内容绘制）时间：

- **优秀 (excellent)**: LCP < 2500ms
- **良好 (good)**: LCP < 4000ms
- **一般 (fair)**: LCP < 5500ms
- **较差 (poor)**: LCP ≥ 5500ms

## 数据存储说明

### 存储位置

数据统一保存在服务器端数据库中，不存储在客户端浏览器。

### 数据提交格式

客户端向服务器提交的数据格式：

```json
{
  "metrics": {
    "FCP": 1234,
    "LCP": 2345,
    "TTFB": 123,
    "CLS": 0.05,
    "FID": 45
  },
  "grade": "good",
  "url": "https://example.com/page"
}
```

### 服务器端存储结构

服务器返回的记录格式：

```json
{
  "id": "记录唯一标识",
  "userId": "用户ID",
  "sessionId": "会话ID",
  "timestamp": "ISO格式时间戳",
  "url": "页面URL",
  "metrics": {
    "FCP": 1234,
    "LCP": 2345,
    "TTFB": 123,
    "CLS": 0.05,
    "FID": 45
  },
  "grade": "good",
  "userAgent": "用户代理字符串"
}
```

### 自动清理机制

- 服务器端每24小时自动检查一次
- 自动删除超过7天的记录
- 管理员也可以手动触发清理

## 注意事项

1. **浏览器兼容性**
   - 需要浏览器支持 Performance API
   - 需要支持 PerformanceObserver API（用于LCP、FCP等指标）

2. **数据收集范围**
   - 系统自动收集所有用户的性能数据
   - 数据统一存储在服务器端
   - 管理员可查看所有用户的聚合统计

3. **隐私保护**
   - 性能数据包含用户ID和会话ID
   - 仅管理员可以访问性能监控页面
   - 所有API请求需要Bearer Token认证
   - 数据仅用于系统性能分析，不会泄露用户隐私

4. **数据准确性**
   - 性能数据受网络环境、设备性能等因素影响
   - 系统收集大量用户样本，统计结果更准确
   - 建议关注趋势而非单个数据点

5. **网络要求**
   - 性能数据提交失败不会影响用户体验（静默失败）
   - 数据提交使用异步方式，不阻塞页面加载

## 技术实现

### 核心文件

1. **性能监控器**: `src/monitoring/performance-monitor.ts` - 客户端自动收集性能指标
2. **API服务**: `src/api/services/performance.service.ts` - 与服务器端通信
3. **API规范**: `docs/api/performance.yaml` - OpenAPI 3.1.0格式的完整API文档
4. **查询界面**: `src/pages/admin/PerformanceMonitorPage.tsx` - 管理员查看所有用户数据
5. **路由配置**: `src/app/App.tsx` - 配置/admin/performance路由

### 工作流程

```
用户访问页面
  ↓
性能监控器自动收集指标（所有用户）
  ↓
计算性能等级
  ↓
通过API提交到服务器 (POST /api/performance/metrics)
  ↓
服务器端存储数据
  ↓
服务器端自动清理超过7天的数据
  ↓
管理员访问 /admin/performance 查看所有用户聚合数据
  ↓
通过API获取统计、记录、最慢页面等信息
```

## API端点详情

完整的API文档请参考：`docs/api/performance.yaml`

### 主要端点

1. **提交性能数据**
   - `POST /api/performance/metrics`
   - 自动从客户端调用，无需手动操作

2. **查询性能记录**
   - `GET /api/performance/records?startDate={}&endDate={}&limit={}&offset={}`
   - 支持时间范围过滤和分页

3. **获取统计数据**
   - `GET /api/performance/statistics?startDate={}&endDate={}`
   - 返回聚合统计（总记录数、平均值、等级分布）

4. **获取最慢页面**
   - `GET /api/performance/slowest-pages?limit={}&startDate={}&endDate={}`
   - 返回加载最慢的页面列表

5. **清理过期数据**
   - `DELETE /api/performance/cleanup`
   - 删除超过7天的记录

6. **清除所有数据**
   - `DELETE /api/performance/clear-all`
   - 删除所有性能记录（需谨慎使用）
