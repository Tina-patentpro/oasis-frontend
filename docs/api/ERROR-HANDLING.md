# 错误处理指南

最后更新：2025-10-22

## 错误分类

| 类型         | HTTP 状态码 | 说明                                   | 前端处理建议                                     |
| ------------ | ----------- | -------------------------------------- | ------------------------------------------------ |
| 认证错误     | 401 / 403   | Token 失效、权限不足                   | 引导重新登录；展示权限提示；必要时触发 `refresh` |
| 参数校验错误 | 400 / 422   | 请求参数不合法、缺失必填字段           | 表单高亮错误字段；根据 `error.details` 渲染提示  |
| 业务冲突     | 409         | 资源状态冲突（如重复执行、工单已关闭） | 显示业务提示，提供重试或刷新选项                 |
| 资源缺失     | 404         | 目标资源不存在                         | 弹出「资源不存在」提示并返回列表页               |
| 限流/配额    | 429         | 超出速率限制或余额不足                 | 提醒用户稍后重试；必要时跳转到 `billing` 页面    |
| 服务异常     | 5xx         | 后端服务不可用                         | 指导用户稍后重试，并上报监控                     |

> 所有标准错误响应均遵循 `ErrorResponse` Schema（见各 OpenAPI 文件）。

## 响应结构

```json
{
  "success": false,
  "error": {
    "code": "WF-409-01",
    "message": "Workflow is already running",
    "details": {
      "executionId": "exec-001"
    }
  }
}
```

- `code`：稳定的业务错误码，支持本地化映射。
- `message`：面向开发者的默认文案。
- `details`：结构化扩展字段，用于指示冲突资源等。

## 前端处理建议

1. **统一拦截器**
   - 在请求层统一捕获 `401/403`，触发 `refresh` 或跳转登录页。
   - 对 `429` 实现指数退避 + 限流提示。
2. **场景化提示**
   - `workflows` 执行冲突（409）提供「查看执行进度」按钮，跳转到 `/api/workflow-executions/{id}`。
   - `billing` 支付失败（400/402）展示渠道返回的 `message`，并提供重新支付入口。
3. **SSE 降级**
   - `conversations` 流式接口若断开（网络错误）自动切换到 `transport=polling`。
4. **监控上报**
   - 记录 `error.code`、`path`、`correlationId`（若后端返回）到 Sentry。

## 错误码约定

| 模块             | 前缀 | 示例                           |
| ---------------- | ---- | ------------------------------ |
| Workflows        | `WF` | `WF-409-01` 执行进行中         |
| Chatflows        | `CF` | `CF-400-02` 指令引用不存在     |
| Conversations    | `CV` | `CV-429-01` 会话发送频率受限   |
| Projects         | `PJ` | `PJ-404-01` 项目不存在         |
| Users/Auth       | `UA` | `UA-401-01` Refresh Token 无效 |
| Billing          | `BI` | `BI-400-03` 支付渠道校验失败   |
| Support/Feedback | `SF` | `SF-409-02` 工单已关闭         |
| Utilities        | `UT` | `UT-403-01` 无权执行导出       |

> 新增模块请在此表补充，确保错误码唯一性。

## 信息泄露防范

- 后端默认隐藏内部异常堆栈，只返回标准错误码与提示。
- 客户端展示文案时需做本地化处理，避免直接渲染后端原始信息。
- API 请求 headers 中敏感字段（Authorization、Signature）不可写入日志。
