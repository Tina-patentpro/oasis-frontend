# API安全策略与权限说明

## 概述

本文档定义了新增API接口的安全策略、权限控制和合规要求，确保系统安全性和用户数据保护。

## 认证与授权

### 1. 认证机制

- **Bearer Token认证**：所有API接口都需要有效的JWT令牌
- **令牌过期**：访问令牌默认2小时过期，刷新令牌30天过期
- **令牌刷新**：支持通过刷新令牌获取新的访问令牌

### 2. 权限模型

```yaml
角色层级:
  - admin: 系统管理员
  - team_admin: 团队管理员
  - user: 普通用户
  - guest: 访客用户

权限范围:
  - read: 读取权限
  - write: 写入权限
  - delete: 删除权限
  - admin: 管理权限
```

## 注册安全策略

### 1. 防刷机制

```yaml
IP级别限制:
  - 注册接口: 5次/小时
  - 验证码发送: 3次/小时
  - 邀请码验证: 20次/小时

用户级别限制:
  - 同一邮箱: 1次/天
  - 同一设备: 3次/天
```

### 2. 验证码安全

- **有效期**：邮箱验证码10分钟有效期
- **复杂度**：6位随机数字，防暴力破解
- **重发限制**：同一邮箱60秒内只能发送一次
- **失败锁定**：连续5次失败验证后锁定15分钟

### 3. 邀请码管理

```yaml
邀请码规则:
  - 格式: INV-YYYY-XXXXX
  - 长度: 12位字符
  - 有效期: 30天
  - 使用次数: 单次使用

安全检查:
  - 域名白名单验证
  - 邀请人权限验证
  - 组织配额检查
```

## 文件安全策略

### 1. 文件类型限制

```yaml
允许的文件类型:
  文档类:
    - application/pdf
    - application/msword
    - application/vnd.openxmlformats-officedocument.*
    - text/plain
    - text/markdown

  图片类:
    - image/jpeg
    - image/png
    - image/gif
    - image/webp
    - image/svg+xml

  压缩包:
    - application/zip
    - application/x-rar-compressed
    - application/x-7z-compressed

禁止的文件类型:
  - 可执行文件 (.exe, .bat, .sh)
  - 脚本文件 (.js, .vbs, .ps1)
  - 系统文件 (.dll, .sys, .drv)
```

### 2. 文件大小限制

```yaml
单文件限制:
  - 普通用户: 10MB
  - 高级用户: 10MB
  - 团队用户: 10MB

批量上传限制:
  - 文件数量: 最大20个
  - 总大小: 最大500MB
  - 并发数: 每用户最多3个并发上传
```

### 3. 病毒扫描流程

```yaml
扫描流程: 1. 上传时实时扫描
  2. 异步深度扫描
  3. 定期全盘扫描

处理策略:
  - 清洁文件: 立即可用
  - 可疑文件: 隔离24小时后人工审核
  - 感染文件: 立即删除并记录日志
  - 扫描失败: 暂时隔离，重试3次
```

### 4. 文件访问控制

```yaml
权限模型:
  所有者权限:
    - read: true
    - write: true
    - delete: true
    - share: true

  团队权限:
    - read: 继承团队设置
    - write: 需要明确授权
    - delete: 仅所有者
    - share: 需要明确授权

  公开访问:
    - read: 需要分享链接
    - write: 禁止
    - delete: 禁止
    - share: 禁止
```

### 5. 文件下载与预览安全

- 服务端必须校验文件真实内容与声明类型，不得只信任扩展名或浏览器上传的 `Content-Type`。
- SVG、HTML、XML 等可能包含可执行内容的文件必须以附件下载，响应必须包含 `Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`。
- 未经过清洗和隔离转换的可执行内容不得在本站同源页面内联预览；需要预览时，应转换为安全的图片或 PDF，并从独立受限域名提供。
- 文件下载接口必须重新检查访问权限，不得依赖前端隐藏按钮作为权限控制。
- 上述响应头与隔离策略必须由服务端或网关实施；前端校验只能用于提前提示，不能作为安全边界。

## 数据隐私保护

### 1. 敏感信息脱敏

```yaml
脱敏策略:
  工作流输入:
    - 密码字段: 完全隐藏 ***
    - 邮箱地址: user***@domain.com
    - 手机号: 138****1234
    - 身份证: 110101********1234
    - 银行卡: 6222****1234

存储策略:
  - 原始数据: 加密存储7天
  - 脱敏数据: 长期存储
  - 审计日志: 存储90天
```

### 2. 访问控制

```yaml
数据访问权限:
  普通用户:
    - 查看自己的执行历史
    - 查看脱敏后的输入数据
    - 不能查看敏感字段

  管理员:
    - 查看所有执行历史
    - 查看原始输入数据（需要特殊权限）
    - 可以导出审计日志

  审计员:
    - 只读访问所有数据
    - 查看完整的审计日志
    - 不能修改任何数据
```

### 3. 数据保留策略

```yaml
保留周期:
  执行记录:
    - 成功记录: 保留2年
    - 失败记录: 保留6个月
    - 已删除记录: 保留30天

  文件存储:
    - 活跃文件: 永久保留
    - 孤立文件: 保留30天后删除
    - 临时文件: 保留24小时

  日志数据:
    - 访问日志: 保留1年
    - 错误日志: 保留6个月
    - 审计日志: 保留3年
```

## 网络安全

### 1. HTTPS强制

- 所有API接口必须通过HTTPS访问
- TLS版本最低要求：1.2
- 支持的加密套件：ECDHE-RSA-AES256-GCM-SHA384

### 2. 请求限制

```yaml
速率限制:
  全局限制:
    - 每IP: 1000请求/分钟
    - 每用户: 500请求/分钟

  接口级别限制:
    - 注册接口: 5次/小时/IP
    - 文件上传: 10次/分钟/用户
    - 查询接口: 100次/分钟/用户
```

### 3. CORS策略

```yaml
允许的域名:
  - 生产环境: https://app.example.com
  - 测试环境: https://test.example.com
  - 开发环境: http://localhost:3000

允许的方法:
  - GET, POST, PUT, DELETE, PATCH, OPTIONS

允许的头部:
  - Content-Type
  - Authorization
  - X-Requested-With
```

## 安全监控

### 1. 异常检测

```yaml
监控指标:
  - 异常登录尝试
  - 大量文件上传
  - 频繁的API调用
  - 权限提升尝试
  - 数据导出行为

告警阈值:
  - 登录失败: 5次/分钟
  - 文件上传: 50次/小时
  - API调用: 1000次/分钟
  - 数据导出: 10次/小时
```

### 2. 审计日志

```yaml
记录内容:
  - 用户认证事件
  - 权限变更操作
  - 文件上传下载
  - 数据修改操作
  - 系统配置变更

日志格式:
  timestamp: ISO8601格式
  user_id: 用户标识
  action: 操作类型
  resource: 操作资源
  result: 操作结果
  ip_address: 客户端IP
  user_agent: 客户端信息
```

## 合规要求

### 1. GDPR合规

- **数据最小化**：只收集必要的用户数据
- **目的限制**：明确告知数据使用目的
- **存储限制**：设定数据保留期限
- **用户权利**：支持数据访问、修改、删除请求
- **数据保护**：实施适当的技术和组织措施

### 2. 数据本地化

```yaml
存储要求:
  - 用户数据存储在境内
  - 敏感数据加密存储
  - 备份数据同样受保护
  - 跨境传输需要额外授权

传输要求:
  - 数据传输全程加密
  - 使用安全的传输协议
  - 定期更新证书
  - 监控传输异常
```

## 应急响应

### 1. 安全事件分类

```yaml
高危事件:
  - 数据泄露
  - 系统入侵
  - 权限提升
  - 恶意软件感染

中危事件:
  - 异常登录
  - 大量数据访问
  - 配置篡改
  - 服务中断

低危事件:
  - 密码泄露
  - 异常API调用
  - 文件异常上传
  - 日志异常
```

### 2. 响应流程

```yaml
发现阶段: 1. 自动监控系统检测
  2. 人工报告确认
  3. 事件分类定级
  4. 启动应急响应

处置阶段: 1. 隔离受影响系统
  2. 收集保全证据
  3. 分析攻击路径
  4. 修复安全漏洞

恢复阶段: 1. 系统安全加固
  2. 数据恢复验证
  3. 监控异常行为
  4. 更新安全策略

总结阶段: 1. 编写事件报告
  2. 总结经验教训
  3. 更新响应流程
  4. 安全培训改进
```
