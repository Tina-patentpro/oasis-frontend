# 前端兼容性与 Polyfill 策略

## 当前支持范围

本项目当前按现代浏览器维护，构建目标见：

- `package.json` 的 `browserslist`
- `vite.config.ts` 的 `build.target`

当前默认目标是 ES2020 级别浏览器能力，不承诺兼容长期未更新的旧版 WebView 或旧版内置浏览器。

## Polyfill 策略

Polyfill（缺失能力补丁）不做全局无差别注入，避免增加所有用户的首屏体积。

只有同时满足以下条件时，才新增 polyfill：

1. 有明确用户场景或测试证据证明目标浏览器缺少该能力。
2. 该能力是核心流程必需能力，不能用更简单的降级提示替代。
3. 优先采用“按功能加载”的方式，只在需要的页面或流程中加载。
4. 新增后必须补充对应测试或最小复现说明。

## 老旧环境处理原则

- 对无法可靠支持的旧 WebView，应显示可理解的升级或换浏览器提示。
- 不为未明确纳入支持范围的浏览器牺牲当前主流程性能。
- 兼容性变更必须经过 `npm run type-check`、`npm run lint`、相关测试和 `npm run build`。

## 当前审计结论

截至本文件新增时，仓库已经显式声明构建目标和 browserslist；本文件补齐“何时引入 polyfill、何时降级提示”的策略说明。
